굵은 항목이 필수다. 나머지는 비워두면 보고서에서 해당 섹션이 생략된다.

## 작성 규칙

섹션 필드는 한 줄에 한 항목이다.

**표로 나오는 섹션** (지난주 완료 산출물, 이번 주 계획)

```
개발 | 신규 병원 생성 기능 구현 | 완료
개발 | DUR 테스트 | 진행중
디자인 | 예약 화면 및 고객관리 모달 샘플 디자인 | 완료
```

`영역 | 내용 | 상태` 순서다. 상태는 생략할 수 있고, `완료` 는 초록, 나머지는 파란
배지로 나온다. 이번 주 계획에는 상태를 쓰지 않는다.

**리스크·이슈**

한 줄에 한 건. 끝에 대괄호를 붙이면 태그가 된다.

```
전체 마이그레이션 목표 완료일에 대한 공식 기준 일정 확인이 필요합니다 [확인 필요]
악성 문자 시스템 구축으로 월 10–15만원 인프라 비용 추가가 예상됩니다 [비용]
```

일정·비용 변동은 반드시 여기에 숫자로 적는다.

**요청사항**

클라이언트가 결정·확인해줘야 하는 것만. 여기 적지 않으면 보고서에 올라가지 않는다.
하위 항목은 줄 앞에 `-` 를 붙인다.

```
DUR 관련 인수인계 업체 일정 확인 요청드립니다.
아래 외부 연동 QA 요청드립니다.
- 전자서명
- 네모닉 출력
- 이지콜/나우테스
```

**지란지교 2단 구성**

`지난주 한 일` / `이번주 할 일` 이 좌우 2단으로 렌더된다. 번호 순서대로 한 줄에 한
항목, 하위 항목은 `-` 로.

## 문체는 신경 쓰지 않는다

대외 보고 문체·태그 정리·직전 회차 이월 대조는 발행 단계에서 처리한다
(`.claude/skills/weekly-report/SKILL.md`). 담당자는 사실만 적으면 된다.

## API 로 못 하는 두 가지

- **문항 순서** — 폼 문항 순서는 API 로 지정할 수 없다. Base UI 에서 한 번
  드래그해 정렬해야 한다.
- **폼 공유 링크** — Base UI 의 폼 공유 설정에서 켜야 외부 링크가 생긴다.
