# 주간 보고 발행

Cofoundary가 각 클라이언트(대표/담당자)에게 매주 월요일 제출하는 정식 보고서를
`clients/<slug>/reports/<YYYY-MM-DD>.yml` 데이터로 만들고 정적 페이지로 발행한다.

## 절차

1. **클라이언트와 기준일 확정.** `clients/` 하위 슬러그 중 하나(`1stcrm`, `byteworks`, `dmax`, `jiranjigyo`).
   기준일은 해당 주 월요일. 불명확하면 묻지 말고 가장 가까운 월요일로 잡고 결과에 명시한다.
2. **직전 회차를 먼저 읽는다.** `clients/<slug>/reports/` 의 마지막 파일(없으면 `legacy/` 의 마지막 HTML).
   이전 회차 없이 이번 주만 보고 쓰지 않는다 — 보고서의 가치는 대부분 "지난주 대비 무엇이 달라졌는가"에 있다.
3. `node src/new-report.mjs <slug> <date>` 로 초안을 만든다. 직전 "이번 주 계획"이 완료 후보로,
   "요청사항"·"리스크"가 이월 상태로 들어온다.
4. **원자료를 초안에 반영한다.** 아래 편집 규칙을 적용한다.
5. `npm run build` 후 `docs/<slug>/<date>.html` 를 실제로 열어 확인한다.
6. 커밋·푸시는 **사용자 승인 후에** 한다. 발행 링크를 알려준다.

## 편집 규칙 — 받아보는 사람 기준으로 다시 쓴다

원자료는 "우리가 무엇을 했는가" 순서로 적혀 있다. 보고서는 "당신의 프로젝트가 어디까지 왔고,
당신이 무엇을 해줘야 하는가" 순서여야 한다.

- **이월 대조를 반드시 한다.** 직전 회차의 "이번 주 계획" 각 항목이 이번에 완료·미완료 중 무엇인지
  확인한다. 원자료에 언급이 없는 항목은 지어내지 말고, 사용자에게 상태를 되묻는다.
- **미완료는 숨기지 않는다.** 사유 한 줄 + 새 목표일을 붙여 "진행중"으로 남긴다.
  근거 없이 "완료"로 올리지 않는다.
- **클라이언트가 해야 할 일은 전부 `요청사항`으로 올린다.** 본문 속에 묻어두지 않는다.
  직전 회차 요청사항 중 아직 회신이 없으면 재요청으로 다시 올린다.
- **일정·비용 변동은 반드시 `이슈 항목`에 숫자로 적는다.** 금액, 날짜, 기간.
- **내부 표현을 지운다.** 저장소명·브랜치·티켓 번호·내부 코드네임·담당자 실명·추측·변명.
  양식 5번(내부 메모)의 내용은 절대 보고서에 싣지 않는다. 리스크 판단의 *결론*만 옮긴다.
- **문체.** 요약·리스크·요청사항은 "~했습니다 / ~합니다 / ~요청드립니다" 체.
  표 안의 항목은 명사형 종결("신규 병원 생성 기능 구현").
- **요약은 3~4문장.** 끝낸 것 → 이번 주 할 것 → 클라이언트가 결정해야 할 것 순서.
- **불확실한 것은 쓰지 않는다.** 원자료에 없는 수치·날짜·완료 판정을 만들어내지 않는다.
  빠진 정보는 보고서에 채우지 말고 사용자에게 목록으로 되묻는다.

## 데이터 스키마

`clients/<slug>/client.yml` — 클라이언트 표시 정보(1회 설정).

리포트 파일:

```yaml
period: 2026.09.21 – 09.27     # 헤더 기간
asOf: 2026.09.21               # 작성 기준일
stats:                         # 상단 3칸 (선택)
  - { label: 보고 기간, value: 09.21–09.27, mono: true }
  - { label: 핵심 마일스톤, value: ... }
  - { label: 전체 상태, pill: { text: 정상 진행, tone: good } }
summary: 3~4문장
sections:
  - type: table                # 영역/내용/상태 표. status 없으면 2열.
    title: 지난주 완료 산출물
    rows:
      - area: 개발
        status: { text: 완료, tone: good }   # tone: good | prog
        items: [항목, 항목]
  - type: notes                # 태그 + 한 줄 (리스크·이슈)
    title: 리스크 및 의존성
    items: [{ tag: 확인 필요, text: ... }]
  - type: card                 # 강조 카드 (요청사항)
    title: 요청사항
    items:
      - text: ...
        sub: [하위 항목]
  - type: dual                 # 좌/우 2단 (제품 단위 보고)
    title: Safe Intelligence
    columns:
      - { label: 지난주 한 일, items: [...] }
      - { label: 이번주 할 일, items: [...] }
  - type: text                 # 자유 문단 카드
    title: 향후 방향
    text: [문단, 문단]
```

항목은 문자열이거나 `{ text, sub: [...] }`. 본문에서 `**굵게**` 만 지원한다.

## 하지 말 것

- `docs/` 를 직접 수정하지 않는다. 빌드 산출물이며 매 빌드마다 지워진다.
- `clients/*/legacy/` 의 기존 HTML을 고치지 않는다. 이미 클라이언트에게 전달된 링크다.
- 승인 없이 push 하지 않는다. push 하는 순간 클라이언트가 볼 수 있는 페이지가 바뀐다.
