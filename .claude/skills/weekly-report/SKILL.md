# 주간 보고 발행

Cofoundary가 클라이언트(대표/담당자)에게 매주 제출하는 보고 페이지를 발행한다.
원본은 **라크 위키 아카이브의 회차 문서**이고, 담당자 작성 방식은 바꾸지 않는다.

```
라크 위키 문서  →  sync  →  reports/<날짜>.yml  →  build  →  docs/  →  Pages
(담당자 작성)                    (다듬는 지점)                        ↓
                                                        Base "주간 보고 링크" 갱신
```

클라이언트 슬러그: `1stcrm` `byteworks` `dmax` `jiranjigyo`.
각 `clients/<slug>/client.yml` 의 `lark.parentNode` 가 위키 폴더, `lark.project` 가
Base 레코드 키다.

## 절차

1. **회차 확정.** 날짜가 불명확하면 `node src/sync-lark.mjs <slug> --list` 로 문서 목록을 본다.
2. **변환.** `node src/sync-lark.mjs <slug> <YYYY-MM-DD>`
   문서를 못 찾거나 같은 날짜가 여러 건이면 `--doc <노드토큰>` 으로 지정한다.
   변환 요약에 `요약 없음` 이 뜨면 그대로 발행하지 말고 사용자에게 알린다.
3. **직전 회차와 대조.** `clients/<slug>/reports/` 의 이전 파일을 읽는다.
   이 대조가 이 스킬의 핵심이다 — 건너뛰면 그냥 변환기와 다를 게 없다.
4. **대외 보고로 다듬는다.** 아래 편집 규칙.
5. **빌드·확인.** `npm run build` 후 `docs/<slug>/<날짜>.html` 을 실제로 열어 본다.
6. **커밋·푸시는 사용자 승인 후.** 푸시하면 클라이언트가 보는 페이지가 바뀐다.
7. **Base 갱신.** `node src/update-base.mjs <slug> <날짜>` 로 미리보기 → 승인 후 `--write`.

## 편집 규칙 — 받아보는 사람 기준으로 다시 쓴다

원본 문서는 "우리가 무엇을 했는가" 순서로 적혀 있다. 보고서는 "당신의 프로젝트가
어디까지 왔고, 당신이 무엇을 해줘야 하는가" 순서여야 한다.

- **이월 대조.** 직전 회차 "이번 주 계획"의 각 항목이 이번에 완료·미완료 중
  무엇인지 확인한다. 원본에 언급이 없는 항목은 지어내지 말고 사용자에게 되묻는다.
- **미완료를 숨기지 않는다.** 사유 한 줄 + 새 목표일을 붙여 `진행중` 으로 남긴다.
  근거 없이 `완료` 로 올리지 않는다.
- **클라이언트가 할 일은 전부 `요청사항`으로.** 본문에 묻어두지 않는다.
  직전 회차 요청사항에 회신이 없으면 재요청으로 다시 올린다.
- **일정·비용 변동은 `이슈 항목`에 숫자로.** 금액, 날짜, 기간.
- **리스크에는 태그를 붙인다.** `확인 필요` `일정 미확정` `비용` `논의 필요` 등.
  원본에 `[일정 미확정]` 처럼 대괄호로 적혀 있으면 변환기가 이미 태그로 올려 둔다.
- **내부 표현을 지운다.** 저장소명·브랜치·티켓 번호·내부 코드네임·담당자 실명·추측·변명.
  원본에 있던 내부 판단 근거는 결론만 남긴다.
- **문체.** 요약·리스크·요청사항은 "~했습니다 / ~합니다 / ~요청드립니다" 체.
  표 안의 항목은 명사형 종결("신규 병원 생성 기능 구현").
- **요약 3~4문장.** 끝낸 것 → 이번 주 할 것 → 클라이언트가 결정해야 할 것.
- **없는 것을 만들지 않는다.** 원본에 없는 수치·날짜·완료 판정은 쓰지 않는다.
  빠진 정보는 채우지 말고 사용자에게 목록으로 되묻는다.

## 데이터 스키마

```yaml
period: 2026.09.21 – 09.27
asOf: 2026.09.21
source: <위키 노드 토큰>        # sync 가 남긴다. Base 갱신에 쓰인다.
stats:                          # 상단 3칸 (선택)
  - { label: 보고 기간, value: 09.21–09.27, mono: true }
  - { label: 핵심 마일스톤, value: ... }
  - { label: 전체 상태, pill: { text: 정상 진행, tone: good } }
summary: 3~4문장
sections:
  - type: table                 # 영역/내용/상태 표. status 없으면 2열
    title: 지난주 완료 산출물
    rows:
      - area: 개발
        status: { text: 완료, tone: good }    # tone: good | prog
        items: [항목, { text: 항목, sub: [하위] }]
  - type: notes                 # 태그 + 한 줄
    title: 리스크 및 의존성
    items: [{ tag: 확인 필요, text: ... }]
  - type: card                  # 강조 카드
    title: 요청사항
    items: [{ text: ..., sub: [...] }]
  - type: dual                  # 좌우 2단
    title: Safe Intelligence
    columns:
      - { label: 지난주 한 일, items: [...] }
      - { label: 이번주 할 일, items: [...] }
  - type: text                  # 자유 문단
    title: 향후 방향
    text: [문단, 문단]
```

본문에서 `**굵게**` 만 지원한다.

## 하지 말 것

- `docs/` 직접 수정. 빌드 산출물이며 매 빌드마다 지워진다.
- `clients/*/legacy/` 의 기존 HTML 수정. 이미 클라이언트에게 전달된 링크다.
- 라크 원본 문서 수정. 담당자의 작업물이다. 보고 내용에 문제가 있으면
  문서를 고치지 말고 사용자에게 알린다.
- 승인 없는 push, 승인 없는 `update-base --write`.
